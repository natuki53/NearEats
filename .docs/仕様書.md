### アプリ名
NearEats

#### コンセプト
「旅行先の食事を迷わず」
NearEatsは、旅行先で土地勘がないときでも、その地域らしい食事を探せるWebアプリです。
現地周辺の飲食店をただ一覧表示するのではなく、ご当地料理カテゴリごとに候補を整理し、お店選びに迷いやすい人が納得して選べる体験を目指します。

#### こだわったポイント
- 旅行先ならではのご飯を見つけやすいよう、現在位置から判定した都道府県に応じてご当地料理カテゴリを表示します。
- 候補を出しすぎて迷わないよう、各カテゴリでは1~2件だけを表示し、さらに見たい場合はカテゴリ詳細画面に進めるようにします。
- メインの導線はご当地カテゴリ検索、サブの導線として通常検索を用意し、目的がはっきりしている場合は細かい条件でも探せるようにします。

- Reactは画面をコンポーネント単位で分けやすく、検索画面、一覧画面、詳細画面を整理して実装しやすいため

### 開発環境構築手順
1. リポジトリを取得します。

```bash
git clone https://github.com/natuki53/NearEats
cd NearEats
```

2. 依存パッケージをインストールします。

```bash
npm install
```

3. 環境変数を設定します。

`.env.sample` をコピーして `.env` を作成します。

```bash
cp .env.sample .env
```

作成した`.env`に、Hot Pepper APIキーを設定します。

```env
HOTPEPPER_API_KEY=<Hot Pepper APIキー>
```

4. 開発サーバーを起動します。

APIキーを使うため、APIプロキシとViteを別々のターミナルで起動します。

```bash
npm run api
```

```bash
npm run dev
```

5. ブラウザで表示します。

```text
http://localhost:5173
```

## アプリケーション機能
### 機能一覧
- 現在地取得: Geolocation APIを使用して、利用者の現在地を取得します。
- 都道府県判定: Geolocation APIで取得した緯度・経度をLocationIQの逆ジオコーディングAPIに渡し、現在地の都道府県を判定します。
- ご当地カテゴリ表示: 都道府県別の簡易辞書をもとに、その地域らしい料理カテゴリを4つ表示します。
- ご当地カテゴリ検索: 各カテゴリのキーワードをHot Pepper APIに渡し、現在地周辺の店舗を検索します。
- カテゴリ別一覧表示: 各カテゴリごとに1~2件の店舗を表示し、候補を絞って見せます。
- カテゴリ詳細表示: さらに見たいカテゴリを選ぶと、そのカテゴリの店舗一覧を表示します。
- 通常検索: キーワード、検索半径、雰囲気条件などを指定して細かく検索できます。
- ページング: 検索結果の件数に応じて、前後のページへ移動できます。
- 店舗詳細表示: 一覧で選択した店舗の詳細情報を表示します。
- 地図アプリ連携: 店舗住所を地図アプリで開けるようにします。
- 公式ページ連携: Hot Pepperの店舗ページへ遷移できるようにします。

## API・データ設計
### 使用API
- ホットペッパー グルメサーチAPI
  - 現在地周辺の店舗検索に使用します。
  - 店舗詳細情報の取得に使用します。
- LocationIQ Reverse Geocoding API
  - 現在地の緯度・経度から都道府県を判定するために使用します。
  - 判定した都道府県をもとに、ご当地料理カテゴリを絞り込みます。

### APIキー管理
Hot Pepper APIのAPIキーは、サーバー側の`.env`に`HOTPEPPER_API_KEY`として定義します。
LocationIQのAccess Tokenは、サーバー側の`.env`に`LOCATIONIQ_ACCESS_TOKEN`として定義します。

フロントエンドから外部APIを直接呼び出すのではなく、APIプロキシが必要なキーを付与してリクエストします。これにより、APIキーやAccess Tokenがブラウザやビルド済みJavaScriptに含まれないようにします。

### 主な利用パラメータ
- `key`: APIキー。サーバー側の`.env`で管理し、APIプロキシからのみHot Pepper APIへ送信する。
- `format`: JavaScript/TypeScriptで扱いやすいよう `json` を指定する。
- `lat`: 緯度。現在地周辺の店舗検索に使用する。
- `lng`: 経度。現在地周辺の店舗検索に使用する。
- `range`: 検索半径。現在地からどの範囲まで検索するかを指定する。
- `keyword`: ご当地料理名、または通常検索キーワード。
- `order`: 並び順。ご当地カテゴリ検索では `4` のおすすめ順を基本とする。
- `start`: 検索開始位置。ページングで次の検索結果を取得するために使用する。
- `count`: 取得件数。1ページあたりに表示する店舗数を指定する。
- `id`: 店舗詳細取得用の店舗ID。
- `genre`: 通常検索でジャンル絞り込みを行う場合に使用する。
- `budget`: 通常検索で予算絞り込みを行う場合に使用する。
- `private_room`: 個室ありで絞り込む場合に使用する。
- `non_smoking`: 禁煙席で絞り込む場合に使用する。
- `english`: 英語メニューありで絞り込む場合に使用する。
- `card`: カード可で絞り込む場合に使用する。
- `lunch`: ランチありで絞り込む場合に使用する。

### 都道府県判定
現在地からご当地カテゴリを表示するため、LocationIQ Reverse Geocoding APIで緯度・経度を住所情報に変換します。

処理の流れ:

1. Geolocation APIで利用者の緯度・経度を取得する。
2. サーバー側のAPIプロキシからLocationIQに問い合わせる。
3. LocationIQのレスポンスに含まれる`address.state`などから都道府県名を取得する。
4. 取得した都道府県名を`localFoodCategories.prefecture`と照合する。
5. 一致するご当地料理カテゴリを表示する。

都道府県名が取得できない場合は、通常検索へ誘導します。

### ご当地料理辞書
DBは使用せず、都道府県別の簡易辞書をアプリ内に持たせます。

例:

| 都道府県 | カテゴリ1 | カテゴリ2 | カテゴリ3 | カテゴリ4 |
| --- | --- | --- | --- | --- |
| 福岡県 | 博多ラーメン | もつ鍋 | 海鮮 | うなぎ |
| 大阪府 | お好み焼き | たこ焼き | 串カツ | うどん |
| 北海道 | 海鮮 | ジンギスカン | スープカレー | ラーメン |

### テーブル定義・ER図
本アプリではデータベースを使用しません。
DBを使用しない理由は、外部APIから最新の店舗情報を取得する構成の方がシンプルで、開発環境構築も容易になるためです。
店舗情報はHot Pepper APIから取得し、フロントエンドの画面状態として保持します。そのため、ER図の代わりに以下のデータ構造を設計対象とします。

- 検索条件
  - 緯度
  - 経度
  - 検索半径
  - キーワード
  - 選択中カテゴリ
  - ページ番号
- 店舗情報
  - 店舗ID
  - 店舗名称
  - 住所
  - アクセス
  - 営業時間
  - ジャンル
  - 予算
  - サムネイル画像
  - 詳細画像
  - Hot Pepper店舗URL

## エラー・例外時の対応
- 現在地取得を拒否された場合は、通常検索または地域選択へ誘導します。
- 検索結果が0件の場合は、検索半径を広げる、または通常検索に切り替える案内を表示します。
- API通信に失敗した場合は、時間を置いて再試行する案内を表示します。
- 画像が存在しない場合は、代替表示を行います。
- 都道府県を判定できない場合は、通常検索を利用できるようにします。
